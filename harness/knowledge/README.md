# Knowledge

Domain knowledge earned while iterating that isn't a requirement in its
own right — patterns noticed, things learned about the problem space,
observations that inform future runs or future harness projects, but
don't belong in `../spec.md` (which is scoped to requirements/generation
rules/evaluation criteria) or `../decisions.md` (which is the raw user
decision log).

One file per topic/theme, e.g. `knowledge/inbox-failure-modes.md` once v1
has been run for a while and we've observed how plain-inbox coordination
breaks down.
